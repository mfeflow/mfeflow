Performance defaults from the Phase 01 spike. `@mfeflow/rsbuild` swaps the CommonJS Module Federation runtime for its ESM build (`esmRuntime`, on by default; the build fails if a `.cjs` has no ESM twin), strips remote-loading code from remotes (`consumesRemotes` opts out), targets the web, and makes the shell ship eager shared singletons with no async bootstrap boundary and no snapshot loader in production builds (`eager`, `snapshot` options). `@mfeflow/runtime` reads the registry from `window.__MFE_REGISTRY__` (replaces `globalThis.mfeflowRegistry`) and falls back to a same-origin fetch of `/registry/index.json`, registers `remoteEntry` URLs in place of manifests, adds the dependency-free `@mfeflow/runtime/plugins/entry-retry` plugin (used by the shell preset), reports a `?mfe-override` that production ignores, and adds `assertRequested()` so the singleton check runs only on request. `@mfeflow/contracts` registry entries and indexes carry `remoteEntry` and per-expose files; new `assetsFromManifest` reads them from `mf-manifest.json` at publish time, and `registryInjection` / `injectIntoHead` build the HTML an edge adds to the shell (inlined registry plus `<link rel="preload">` hints).

A production shell has no manifest loader, so it cannot load a registry entry that has only a manifest URL. Nothing writes `remoteEntry` at publish yet, so this fails loudly instead of silently: the shell build defines `__MFEFLOW_SNAPSHOT__`, and `registerRemotesFromIndex` skips such a remote and reports it (`where: 'registry'`, message starting `MFE_NO_REMOTE_ENTRY`, with `mfe` set to the remote's name). Build the shell with `snapshot: true` to keep the loader until publishing writes `remoteEntry`. Registry entries also carry the entry `type` (for example `module` for ESM) and `entryGlobalName`, and `assetsFromManifest` reads both from the manifest and joins paths the way Module Federation does.

The shell preset throws if `eager: false` is set but the entry has no `import()` boundary. Registry validators and the runtime accept only Module Federation entry types and a valid `entryGlobalName`; `registryInjection` inlines version, owner and routes, uses `modulepreload` for ESM remotes and preloads the manifest of a manifest-only remote only when the new `snapshot: true` option says the shell can load it (default false, like the production shell preset).
