# i18n

Translations with `@mfeflow/i18n`. The shell starts one i18next instance; each remote loads its own messages from its
own deploy. Off by default.

```sh
pnpm mfeflow add i18n
```

## What you get

| File                                         | What it is for                                                                                                        |
| -------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `apps/shell/src/i18n/config.ts`              | The language list, the default language and the shell's own messages. English and Arabic to start.                    |
| `apps/shell/src/i18n/init.ts`                | The boot step: `initI18n(...)`, awaited before the first render.                                                      |
| `apps/shell/src/i18n/LanguageSwitcher.tsx`   | A language picker. Yours: move it, restyle it.                                                                        |
| `apps/<remote>/src/i18n/messages/<lng>.json` | The remote's messages, one file per language. Each becomes its own chunk, served from the remote's deploy.            |
| `apps/<remote>/src/i18n/I18n.tsx`            | Wraps the remote's `App`. Shows a greeting from the messages, and starts i18n itself when the remote runs on its own. |
| `apps/<remote>/src/i18n/load.ts`             | The loader for `useMfeTranslation`.                                                                                   |

## Using it in a remote

```tsx
import { useMfeTranslation } from '@mfeflow/i18n/react';
import { loadMessages } from './i18n/load';

export function Title() {
  const { t } = useMfeTranslation('cart', loadMessages);
  return <h2>{t('hello')}</h2>;
}
```

The namespace is the remote's name. The messages for the current language load when the component mounts and again
when the language changes; if one language fails to load, the default language's messages are used so the text never
disappears.

A translation ships with the remote that uses it. Deploying the cart with a fixed message does not touch the shell
or the catalog.

## Language and direction

Changing the language sets `<html lang>` and `<html dir>` (`rtl` for Arabic, Hebrew and the others i18next knows),
and the choice is saved under the shell's storage. Add a language in `config.ts`, then add `<code>.json` to each
remote. A remote without the file falls back to the default language.

Use CSS logical properties (`margin-inline-start`, `padding-inline`) in remotes, so `dir` is all a right-to-left
language needs.

## Singletons

`i18next` and `react-i18next` are shared singletons (the shell provides them; `mfeflow doctor` checks that every
app uses one version). The shell and the remotes install the same pinned versions.

## Standalone remotes

`pnpm dev` inside a remote runs it without the shell. `I18n.tsx` notices there is no instance and starts one with the
remote's own language list, so the page still shows translated text.
