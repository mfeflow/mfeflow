## 0.1.0

### Minor Changes

- [#21](https://github.com/mfeflow/mfeflow/pull/21) [`aaf6524`](https://github.com/mfeflow/mfeflow/commit/aaf65244bf7f025d56f262d534208c3f4786a1f1) Thanks [@speedsharmaai](https://github.com/speedsharmaai)! - `mfeflow add env-key <KEY> --scope server|runtime --schema <expr>` adds a typed env key to `env.ts` or the runtime-config schema, `.env.example` or every runtime-config file, and `turbo.json`. `mfeflow doctor` checks `.env.example`, the runtime-config files, `PUBLIC_*` use and `turbo.json` against the schema once `env-t3` is installed (E118 to E121). The `mfeflow` package is linked by `--local` like the `@mfeflow/*` ones.

- [#19](https://github.com/mfeflow/mfeflow/pull/19) [`3fb82a3`](https://github.com/mfeflow/mfeflow/commit/3fb82a3ae0c2fb6d3ecb610a252ad8a659066458) Thanks [@speedsharmaai](https://github.com/speedsharmaai)! - `mfeflow init`, `add remote`, `add shell`, `add <feature>` and `features`, and `npm create mfeflow@latest`, which runs `init`.
  
  `init` writes a pnpm 12 workspace with Turborepo, a shell and remotes (default `catalog` and `cart`) as thin configs over `@mfeflow/rsbuild`, a registry per environment, and the first-party features `core`, `tsconfig`, `lint-oxlint`, `url-factory` and `git-hooks`. `pnpm dev` in the result starts the shell and every remote, with a dev registry pointing at their dev servers. Every command takes `--yes`, `--preset`, `--json` (schema-checked output), `--dry-run` (summary and diff, nothing written), `--cwd`, `--no-install` and `--verbose`; errors print `MFEFLOW_Exxx`, a fix and a docs link, with stable exit codes. `--local <checkout>` links `@mfeflow/*` from a built clone so a project can be generated and run before anything is on npm.
  
  `@mfeflow/core` exports `inOrder`, `hasErrno` and `messageOf`, gives templates `app.port`, lets a `PlanBuilder` rewrite dependency ranges (`rewriteRange`), and adds the error codes `E107` to `E110` and `E215`. `@mfeflow/contracts` accepts an optional `port` on each app in `mfeflow.json`.
  
  Migration: app and remote names (`MFE_NAME` in `@mfeflow/contracts`) are now lowercase words of letters and digits joined by single underscores, such as `order_history`. A name that ends in `_`, has `__`, or has `_` before a digit (`cart_`, `a__b`, `a_1`) is refused, because it would produce the same route component as another name; rename the app and its `mfe.json` and `registry` entry. `@mfeflow/core` also exports `readCappedText`, the size-capped body reader `fetchRemoteText` uses.
  
  Registry URL templates may contain `{version}`; `add shell` and `add remote` use it to fetch each installed registry feature at the version `mfeflow.json` recorded, refuse when the registry serves another one, and ask for the same confirmation as `add <feature>`.

- [#20](https://github.com/mfeflow/mfeflow/pull/20) [`b7b08a6`](https://github.com/mfeflow/mfeflow/commit/b7b08a65f341097ee3a4d7676ad5cc732fd333f1) Thanks [@speedsharmaai](https://github.com/speedsharmaai)! - `mfeflow dev` runs the shell and every remote with one command: a coloured, prefixed log per app, `--only a,b` for part of the project, and `--remote name=url` to use a server you run yourself (localhost only unless `--allow-origin` names the origin). It writes the dev registry the shell reads to `.mfeflow/dev-registry.json` and rewrites it when `mfeflow.json` or `registry/envs/dev` changes, so `mfeflow add remote` no longer needs a restart: the shell restarts itself and the new remote is started. Ctrl+C stops every app and its children (`taskkill /T` on Windows) and exits 130. The generated shell config reads `MFEFLOW_DEV_REGISTRY` when set and watches the registry; plain `pnpm dev` is unchanged.
  
  `mfeflow doctor` checks that every app is on disk, `mfe.json` and the registry entries are valid, ports and routes are unique, the linked checkout is built, each singleton (react, react-dom, …) is one version across the apps, every workspace package has a version, remotes fit their shell, copied files match their hashes and runtime plugins import nothing shared. `--fix` writes missing registry entries and missing workspace versions. `mfeflow validate` and `mfeflow check-compat` run the schema and compatibility parts, and `mfeflow budget` measures the built shell and remotes against the cost-model budget. All four take `--json` (schema-checked) and exit non-zero on errors. The generated README and AGENTS.md document them.
  
  Migration: none. `.mfeflow/` is added to the generated `.gitignore`.

- [#24](https://github.com/mfeflow/mfeflow/pull/24) [`bdb8cee`](https://github.com/mfeflow/mfeflow/commit/bdb8ceeafb5f711fce106fabfb9800eb829fded7) Thanks [@speedsharmaai](https://github.com/speedsharmaai)! - Add the `analytics-gtm` and `telemetry-otel` features. `analytics-gtm` starts Google Tag Manager with Consent Mode v2 from the runtime config's `gtmId`, wraps the shell for page views and a consent banner, and gives each remote a typed `analytics.ts`. `telemetry-otel` loads the OpenTelemetry SDK after first render when the runtime config has an `otlpEndpoint`, reports remote failures, and gives each remote a `telemetry.ts` tracer tagged with its name. Both put their keys in the env-t3 runtime config when env-t3 is installed, whichever was added first, and in `public/config/runtime-config.json` otherwise.
