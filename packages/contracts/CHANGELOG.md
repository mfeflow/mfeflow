## 0.1.0

### Minor Changes

- [#19](https://github.com/mfeflow/mfeflow/pull/19) [`3fb82a3`](https://github.com/mfeflow/mfeflow/commit/3fb82a3ae0c2fb6d3ecb610a252ad8a659066458) Thanks [@speedsharmaai](https://github.com/speedsharmaai)! - `mfeflow init`, `add remote`, `add shell`, `add <feature>` and `features`, and `npm create mfeflow@latest`, which runs `init`.
  
  `init` writes a pnpm 12 workspace with Turborepo, a shell and remotes (default `catalog` and `cart`) as thin configs over `@mfeflow/rsbuild`, a registry per environment, and the first-party features `core`, `tsconfig`, `lint-oxlint`, `url-factory` and `git-hooks`. `pnpm dev` in the result starts the shell and every remote, with a dev registry pointing at their dev servers. Every command takes `--yes`, `--preset`, `--json` (schema-checked output), `--dry-run` (summary and diff, nothing written), `--cwd`, `--no-install` and `--verbose`; errors print `MFEFLOW_Exxx`, a fix and a docs link, with stable exit codes. `--local <checkout>` links `@mfeflow/*` from a built clone so a project can be generated and run before anything is on npm.
  
  `@mfeflow/core` exports `inOrder`, `hasErrno` and `messageOf`, gives templates `app.port`, lets a `PlanBuilder` rewrite dependency ranges (`rewriteRange`), and adds the error codes `E107` to `E110` and `E215`. `@mfeflow/contracts` accepts an optional `port` on each app in `mfeflow.json`.
  
  Migration: app and remote names (`MFE_NAME` in `@mfeflow/contracts`) are now lowercase words of letters and digits joined by single underscores, such as `order_history`. A name that ends in `_`, has `__`, or has `_` before a digit (`cart_`, `a__b`, `a_1`) is refused, because it would produce the same route component as another name; rename the app and its `mfe.json` and `registry` entry. `@mfeflow/core` also exports `readCappedText`, the size-capped body reader `fetchRemoteText` uses.
  
  Registry URL templates may contain `{version}`; `add shell` and `add remote` use it to fetch each installed registry feature at the version `mfeflow.json` recorded, refuse when the registry serves another one, and ask for the same confirmation as `add <feature>`.

- [#21](https://github.com/mfeflow/mfeflow/pull/21) [`aaf6524`](https://github.com/mfeflow/mfeflow/commit/aaf65244bf7f025d56f262d534208c3f4786a1f1) Thanks [@speedsharmaai](https://github.com/speedsharmaai)! - A feature's files, dependencies, scripts and transforms can carry `when: { option: value }`, so an option such as a validator library decides which parts apply.

- [#13](https://github.com/mfeflow/mfeflow/pull/13) [`c4a5a2b`](https://github.com/mfeflow/mfeflow/commit/c4a5a2bceba5c22413923dafc956abc00432438c) Thanks [@speedsharmaai](https://github.com/speedsharmaai)! - Breaking (0.x): `assetsFromManifest` joins a `publicPath` like Module Federation's `getResourceUrl` (`${publicPath}${file}`). A relative or root-relative `publicPath` resolves against the shell page, so pass `{ pageUrl }` as the third argument; without it the remote comes back manifest-only with a reason. `auto` and empty still use the manifest's directory. With `metaData.getPublicPath` the URLs are computed in the browser, so the result has no `remoteEntry`, empty `exposes` and a `manifestOnly` reason: publish that remote by manifest URL. Every URL returned is absolute, so the output always passes the registry validators. `RemoteAssets.remoteEntry` is now optional.

- [#13](https://github.com/mfeflow/mfeflow/pull/13) [`c4a5a2b`](https://github.com/mfeflow/mfeflow/commit/c4a5a2bceba5c22413923dafc956abc00432438c) Thanks [@speedsharmaai](https://github.com/speedsharmaai)! - Performance defaults from the Phase 01 spike. `@mfeflow/rsbuild` swaps the CommonJS Module Federation runtime for its ESM build (`esmRuntime`, on by default; the build fails if a `.cjs` has no ESM twin), strips remote-loading code from remotes (`consumesRemotes` opts out), targets the web, and makes the shell ship eager shared singletons with no async bootstrap boundary and no snapshot loader in production builds (`eager`, `snapshot` options). `@mfeflow/runtime` reads the registry from `window.__MFE_REGISTRY__` (replaces `globalThis.mfeflowRegistry`) and falls back to a same-origin fetch of `/registry/index.json`, registers `remoteEntry` URLs in place of manifests, adds the dependency-free `@mfeflow/runtime/plugins/entry-retry` plugin (used by the shell preset), reports a `?mfe-override` that production ignores, and adds `assertRequested()` so the singleton check runs only on request. `@mfeflow/contracts` registry entries and indexes carry `remoteEntry` and per-expose files; new `assetsFromManifest` reads them from `mf-manifest.json` at publish time, and `registryInjection` / `injectIntoHead` build the HTML an edge adds to the shell (inlined registry plus `<link rel="preload">` hints).
  
  A production shell has no manifest loader, so it cannot load a registry entry that has only a manifest URL. Nothing writes `remoteEntry` at publish yet, so this fails loudly instead of silently: the shell build defines `__MFEFLOW_SNAPSHOT__`, and `registerRemotesFromIndex` skips such a remote and reports it (`where: 'registry'`, message starting `MFE_NO_REMOTE_ENTRY`, with `mfe` set to the remote's name). Build the shell with `snapshot: true` to keep the loader until publishing writes `remoteEntry`. Registry entries also carry the entry `type` (for example `module` for ESM) and `entryGlobalName`, and `assetsFromManifest` reads both from the manifest and joins paths the way Module Federation does.
  
  The shell preset throws if `eager: false` is set but the entry has no `import()` boundary. Registry validators and the runtime accept only Module Federation entry types and a valid `entryGlobalName`; `registryInjection` inlines version, owner and routes, uses `modulepreload` for ESM remotes and preloads the manifest of a manifest-only remote only when the new `snapshot: true` option says the shell can load it (default false, like the production shell preset).
